# Bootstrap a fresh Linux/WSL machine (#83)

**Debian/Ubuntu/WSL only. As of 2026-11-06.** Four commands take a blank machine to a managed zsh shell; `tools/bootstrap-linux.sh` is idempotent, so re-run it to repair. The package set is `tools/lib/packages.tsv`, shared with the macOS script — see [bootstrap-packages.md](bootstrap-packages.md). macOS: [bootstrap-mac.md](bootstrap-mac.md).

## Sequence

| # | Command | Why |
| --- | --- | --- |
| 0 | `sudo apt update && sudo apt install -y curl git` | Needed to fetch the script and for chezmoi itself |
| 1 | `curl -fsSL https://raw.githubusercontent.com/IdahoEv/dotfiles/main/tools/bootstrap-linux.sh -o /tmp/bootstrap-linux.sh` | Runs before chezmoi, so it can't come from the deploy clone; it fetches `tools/lib/packages.tsv` itself |
| 2 | `bash /tmp/bootstrap-linux.sh` | Installs the manifest's packages, `gh`, `oh-my-posh`, `chezmoi`, `uv`, `fnm`; sets zsh as login shell |
| 3 | `~/.local/bin/chezmoi init --apply IdahoEv/dotfiles` | Prompts for git email, work-machine flag, and 1Password shell-plugin flag, then applies |
| 4 | `exec zsh` | Start the managed shell; run after step 3 so zsh does not open its first-run setup menu (a full WSL restart makes `chsh` take effect for new terminals) |

Step 3 writes `~/.config/chezmoi/chezmoi.toml` from `.chezmoi.toml.tmpl`. Machines that already have that file are not re-prompted. It holds no secrets: API tokens live in 1Password and are resolved by `op` at run time (see `run_onchange_after_register-mcp-servers.sh`). A file generated by an earlier version may still hold `notion_api_token`, `shortcut_api_token` or `anthropic_api_key`; the register script deletes those lines on its next run (and removes the old `notion`/`shortcut` MCP entries from `~/.claude.json`); rotate the tokens.

## What the script does

| Step | Equivalent by hand |
| --- | --- |
| core + dev packages | `sudo apt-get install -y` the manifest's `apt` column for those tiers; failure aborts |
| search packages | Same, but only those `apt-cache show` finds; the rest are reported and skipped (older Ubuntu lacks `eza`, `git-delta`) |
| `gh` | [GitHub's apt repo instructions](https://github.com/cli/cli/blob/trunk/docs/install_linux.md); skip with `--skip-gh` |
| `oh-my-posh` | Download `posh-linux-<arch>` from the latest [release](https://github.com/JanDeDobbeleer/oh-my-posh/releases) to `~/.local/bin/oh-my-posh`, `chmod +x` |
| `chezmoi` | Download `chezmoi-linux-<arch>` from the latest [release](https://github.com/twpayne/chezmoi/releases) to `~/.local/bin/chezmoi`, `chmod +x` |
| `uv` | `UV_UNMANAGED_INSTALL=~/.local/bin` with [astral.sh/uv/install.sh](https://astral.sh/uv/install.sh) |
| `fnm` | [fnm.vercel.app/install](https://fnm.vercel.app/install) with `--install-dir ~/.local/bin --skip-shell` |
| `fd` / `bat` shims | `ln -s "$(command -v fdfind)" ~/.local/bin/fd`, same for `batcat` → `bat` |
| Login shell | `sudo chsh -s "$(command -v zsh)" "$USER"` |

Binaries and installers are fetched over HTTPS without checksum verification. Only `amd64` and `arm64` are supported. The distro's `python3` may be older than the repo's 3.13 floor on LTS releases; `uv python install 3.13` covers that.

## WSL notes

- **Bash default:** WSL launches the `/etc/passwd` login shell, so `chsh` to zsh bypasses the distro's unmanaged `~/.bashrc`.
- **IPv6 stalls:** if outbound calls (including this script's downloads) hang on an unrouted IPv6 path, prefer IPv4:

  ```sh
  echo 'precedence ::ffff:0:0/96  100' | sudo tee -a /etc/gai.conf
  ```

  This is a system-wide resolver setting, so the script does not change it.
- **Fonts:** the oh-my-posh theme needs a Nerd Font in the terminal. On WSL that is a Windows-side install; the script cannot do it.
- **No `oh-my-posh`:** zsh falls back to a plain `user@host dir %` prompt rather than the inherited bash `PS1`.
